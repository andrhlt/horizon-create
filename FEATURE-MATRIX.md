# Create feature matrix

Reference build is Create 6.0.10 for NeoForge on Minecraft 1.21.1, commit
`ac0c444d9828da3453ae8cc65338e8de063286fb`. The catalog uses the pinned
Java registries and gameplay source. Statuses use the [parity report](PARITY.md),
[Horizon replay runner](tools/test-parity.py), and the isolated builds recorded
for those replays. The registry baseline is the audited
`native-9f42064-352d59d17c49` build from November 18, 2026. Build rollout
to Create Parity Lab is tracked separately.

| Column | Meaning |
| --- | --- |
| In game | **Yes** means the family has a playable Horizon path. **Partial** means at least one variant or path is available and other original paths remain open. **Candidate** means implementation or verification is in progress. **Missing** means the audited build has no playable equivalent in the reviewed scope. **Review** means evidence is insufficient to determine availability. |
| Basic tested | **Pass** means at least one representative, repeatable Horizon gameplay check passed. **Partial** means coverage is limited to a subset, a control, or data and assets. **Open** needs an applicable Horizon replay. |
| Java comparison | Names the fields or scenarios compared with original Java Create. A registry check establishes exact ID availability. A gameplay fixture comparison establishes the sampled states, ticks or outputs. |
| Full 1:1 | **Open** until every applicable gameplay path, variant, rendering and audio effect, multiplayer role, and save/reopen behavior in the row is verified. Read the preceding comparison column for completed exact scopes. |

Gameplay ticket completion follows [the finite completion standard](COMPLETION-STANDARD.md).
A merged gameplay ticket may be Done while its Full 1:1 column remains Open;
the two measure different levels of evidence.
